# Joan 那把尺：同一個判準滲透每一層決策

> [!abstract] 這張卡是什麼
> 學 Joan **不是**背她的六問、七個 prompt 或治理清單——那些是尺的刻度。真正要學的是：**有一把自己的尺，並且讓它滲透到每一層決策**。她自己講得最白：「工具會換，這把腦內思考的尺不會隨便換，這也是我一直想教學員的：怎麼練出這把尺。」下面所有 pattern 卡，都是這把尺切出來的某一面。

## 這把尺的兩個特徵

**① 滲透性——同一判準從商業策略一路鑽到最底層技術決策**
Joan 回看自己六份開發指令才驚覺：「我不是只有一套六步驟方法論，是這套方法論長了觸角，從商業策略一路鑽到資料庫 schema，鑽到系統怎麼失效、失效了通知誰、通知了誰要負責。」
- 「先問錢在哪」不停在商業層，滲透到「後端用 Neon 不要超過免費門檻」「索引盡量重複使用」——連 DB schema 都在替預算著想。
- 判準是同一把：從「要不要開一個新功能」到「索引要不要重複使用」，用的都是同一把尺。

**② 彈性——場景情緒濃度越高，尺會自動長出新的一層**
「原來我那套骨架不是死的，是有彈性的，場景的情緒濃度越高，就會自動長出新的一層疊加上去。」
- 前六份指令防的是數字算錯、AI 幻覺、供應鏈斷；到了寵物殯葬平台（高情緒場景），自動長出**情緒風險治理**（防的不是講錯事實，是語氣讓剛失去寵物的人更痛）、**信仰立場建模**（立場從「角色職能」升級到「個人信念系統」）。
- 框架的完整性不是靠「把所有情況預先列進清單」，是靠「骨架有沒有彈性長出新層」。

## 為什麼這是學 Joan 的 checkpoint（而不是又一句大道理）
一般人學高手，是抄他的招式清單（六問、prompt 模板）。但招式離開那把尺就是散裝技巧，套錯場景就垮。真正可遷移的是「**練出一把自己的尺 + 讓它滲透每一層 + 讓它在壓力下長出新層**」這件事本身。這也是為什麼她的判斷「隔行不隔理」——尺量的是財務／風險結構，不是產業知識。
